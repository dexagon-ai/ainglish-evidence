# Full-claim comprehension designs — execution held

These designs expand the earlier focused 256-cell kits. They are **not completed
measurements**, not reader qualification and not frozen target manifests ready to
mint. No target reader has been called on them. The current cost prerequisites
failed their new point tests; independent settlement and author assessment come
before any dependent full-claim execution. Earlier predictions/results are not
rewritten. Complete concrete input/gold manifests and exact reader provenance
must be publicly frozen before any future target exposure.

## Reply and non-reply: coverage contract

Use at least 16 domain frames and 256 distinct semantic worlds, balanced over both
forms. Domains should include invitations, approvals, scheduling, hiring,
editorial review, procurement, bookings, support, maintenance, teaching,
volunteering, laboratory access, lending, delivery, data sharing and event plans.
Lexical substitutions within one frame are correlated cells, not independent
domains. Freeze the domain-level weighting and cluster uncertainty rule first.

| Required distinction | Facts that both explicit arms must show | Question and guard |
| --- | --- | --- |
| Negative response / scoped non-observation | Named actor, exact request, channel and cutoff | Is a responsive answer known? Is a negative stance known? Unknown is not false. |
| Confirmed / unknown delivery | An explicit read receipt or delivery-unknown statement | Was delivery established? A response marker is not a transport receipt. |
| Exact / wrong request revision | Both revision IDs and which was answered | An answer to R2 does not answer changed R3. |
| Other channel / later answer | A visible chat answer or a time after the observation cutoff | An email non-observation remains compatible; never grade hidden world history. |
| Qualified refusal | The actual qualification, such as not this week | Refusal is scoped, not permanent. |
| Workflow policy | Explicit go / hold / undecided instruction, independently balanced | The policy determines routing; silence is not permission or consent. |
| Attribution failure | Auto-reply, unauthorised delegate or ambiguous emoji | Do not invent an attributable responsive answer. |

The complete careful-English arm carries every relevant actor/request/channel/
time/policy fact. The Ainglish arm changes only the claimed relation surface.
A separately labelled bare-status diagnostic uses exactly identical ambiguous
status wording in balanced latent worlds. It measures recovery with missing
information, **not** non-inferiority to complete English; never pool its gains
with that primary comparison or reveal the gold through IDs/order.

Primary report: full answer vector and the stated reply-existence/negative-stance
pair, both forms, all domain/channel/time cells and absolute arm accuracy. Keep
the original ≥25pp bare-status recovery prediction separate from the 5pp
per-form non-inferiority requirement. False refusal, fabricated receipt and
permission/consent inference are critical errors, reported against the stated
5% bound with denominators and uncertainty. A non-significant difference is not
evidence of non-inferiority.

Hard negatives explicitly include bounce, read-without-answer, not-this-week,
wrong revision, negative answer in another channel, answer one minute later,
out-of-office text, unauthorised delegation, emoji-only response and a policy
that treats silence operationally as declined. The last case changes workflow,
not what communication actually occurred.

## Identity and equality: coverage contract

Use at least 16 domain frames and 256 semantic worlds balanced over both forms.
Include physical copies, editions, documents, files, hardlinks, accounts,
containers, model processes, museum objects, parcels, bookings, database records,
keys, instruments, artworks and balances. Explicitly resolve X, Y, the equality
key and the observation time in both arms. Surface IDs must not encode the gold.

| Required distinction | Explicit facts in both arms | Consequence to score |
| --- | --- | --- |
| Alias of one instance | Domain identity rule and references | Count entities; return the original; propagate a mutation only under that rule. |
| Distinct but equal values | Equal named projection and, when known, distinctness stated separately | Whether a substitute satisfies a value-only requirement. |
| Equal on K, unequal on J | Both values or a named comparison record | Licence only the named key, not every property. |
| One changing instance | Current identity plus explicit historical snapshots | Identity does not imply an unchanged value history. |
| Alike names / different aliases | Resolved referents independent of label spelling | Do not infer identity from names or difference from different names. |
| Missing, unresolved or non-unique key | Omit exactly the required information in both arms | Clarify; do not guess an equality relation. |
| Past equality | A past epoch and no current observation | Recheck before treating equality as current. |

Primary report: full action/consequence vector, per-form non-inferiority within
5pp, absolute accuracies, all domains and key/time/identity-history strata. The
two critical errors are “value-equal implies distinct” and “same-instance implies
unchanged history”, with the original 5% maximum retained. Keep the ≥25pp gain
against ambiguous bare “same” diagnostic separate from complete-English results.
Balance cases where a value-equal pair is one instance, distinct instances, or
has unresolved identity; the marker alone cannot disclose a hidden identity bit.

Hard negatives include title versus edition, ISBN versus physical-copy barcode,
hardlinks versus equal checksums, account values at different times, container
image versus running container, mutable document history, non-unique keys and
unresolved references. An action question must supply the actual domain rule;
do not smuggle programming-language mutation semantics into physical objects.

## Edit robustness and future execution

For each design, freeze a distinct mutation schedule covering hyphen/case/
punctuation changes, omitted arguments, wrong references, key substitution,
polarity loss and stale time/channel information. State which edits should
preserve meaning and which make the message invalid or under-specified. Score
unlicensed silent recovery separately from visible clarification. An edit that
changes the claim must not be graded as though the original gold still holds.

Before execution: reconcile every row against the live mapping/prediction;
publish complete visible texts and independently auditable gold; run exhaustive
world-consistency and balanced-label tests; qualify the exact interface with
fresh target-independent controls; freeze model digests, system, decoding,
context/output caps, calibration, exclusions and stop rules; mint before spend.
Record all refusals, truncations and failed gates. No automatic retries,
post-hoc answer parser, shorter comparator or favourable subgroup selection.

Any new full-world text needs its own matching complete-claim token bridge. The
existing token result cannot be passed off as a test of newly expanded strings.
These are currently held designs, not a request to raise the cost thresholds or
to spend a reader run merely because a GPU is free.
