# Three candidate packets for author and independent instrument review

Status: **review drafts, not scientific launch freezes**. No reader or tokenizer
call, attempt mint, measured finding or claim of independent confirmation.
`build_candidates.py` reproduces every bank and key; `candidate-manifest.json`
pins the parsed JSON arrays. Every source world is explicitly synthetic.

An additional 16 hand-written semantic regression checks cover threshold equality,
adjusted versus raw p, changing uncertainty at a fixed estimate, post-hoc records,
wrong/missing references, materialised defaults, re-resolution, non-unique edits,
machine-written assignments and temporal anchoring. These are design expectations,
not independent reviewer approvals or scored observations.

Each full review row retains marked/careful/bare renderings, complete question and
options, explicit gold per comparison, record, domain and template/world labels.
The `*.careful-panel-draft.json` exports use existing SDK item fields. They are
structurally inspectable without becoming runnable study specifications: there is
no reader roster, calibration, approval, attempt or submit command in this packet.
Declarations can be checked with the proposed SDK sidecar audit (see the PR).

## What the preparation actually found

1. **Ledger/trace answer leakage through shared context:** latest and assignment
   cases deliberately make the governing records recoverable. For these particular
   questions the records alone determine the answer. These are useful semantic
   regression tests, but a language comparison using them can have no headroom.
   More GPU calls would not fix that. Before a causal wording study, specify the
   realistic communication task and a context-only ablation. Retain facts needed
   to verify meaning without silently giving one arm extra answer-bearing facts.
2. **Bare-arm hidden intent:** every statistical bare placeholder is deliberately
   underspecified, with the same “cannot determine both rules” key. The marked and
   careful reports have a determinate key. Those are different information states,
   not a paired same-gold official comprehension comparison. The placeholder
   `significance discussed` is a disclosed missing-information test, **not a fair
   ordinary-English control or a source-corpus sample**. No bare panel is exported.
   A real bare comparator needs the source context and prospective sampling rule.
3. **Clustering:** 456 IDs are not 456 independent semantic frames. There are 16,
   4 and 14 template families respectively, reused across domain labels and values.
   Those counts are visible, not hidden behind a large denominator. A final bank
   needs reviewed scenario diversity and an uncertainty method respecting its
   actual sampling/reader/item clusters. Domain names alone do not create it.
4. **Not all rows answer all promises:** statistical core cases jointly report both
   statuses. Correct joint classification does not by itself establish the two
   single-marker false-inference ceilings. Latest/assignment core choices do not
   jointly score a justification boundary. The supplementary checks identify what
   additional instrument components need validation; no unchecked endpoint is
   silently marked complete.

## Per-candidate launch decisions

### Latest/final

- Author chooses a genuine carrier/comparator route, using the acceptance-decision
  paper rather than asserting careful-English superiority solely to fit a gate.
- Accept/reject the supplied semantic keys. The valid-final/not-latest-at-the-same-
  closure-point cell is impossible; false assertions and historical/current
  mismatches stay explicit diagnostics, not a manufactured fourth valid meaning.
- Design consequence-plus-boundary scoring, per-form 90% floor, two 5% error caps,
  declared domain/closure/reopening summaries and valid preservation uncertainty.
- Review a context-only witness before reader spend. Report an unavoidable ceiling
  honestly; do not obscure the ledger merely to force an advantage.

### Statistical/practical

- Resolve the existing token original's population, reference aliases and precise
  comparator scope with its author. That token row does not decide the reader claim.
- Review all four joint classifications and add separately scored single-marker
  non-entailment probes. Preserve post-hoc status and named nulls; do not score a
  generic “no effect” conclusion from a non-rejection.
- Choose realistic source-grounded bare prose if claiming that benefit. Score each
  complete visible input on what it actually provides, not an unseen intended state.
- Specify per-marker recovery, joint-state recovery, the 25-point bare contrast,
  both 5% false-inference caps and preservation as separate estimands/checks.

### Assignment/default

- Confirm the resolver rules and the run-local identity convention in the examples.
  An actual retained environment field or argv occurrence can be a reference;
  a global persistent ID is not mandatory. Missing traces remain a usability limit.
- Decide the intended downstream task. Provenance alone does not determine which
  one edit “must” occur or whether a future rule change affects a materialised value.
  Include an explicit re-resolution/intervention rule, or use an unknown answer.
- Keep the 24 boundary rows distinct from the 144 assignment/default cases. Neither
  rejected resolution nor unavailable provenance is a third successful marker form.
- Review context-only headroom and separate per-form recovery/error caps before
  qualifying readers. An assignment equal to a default remains an assignment.

## Common prospective study plan — unresolved choices, not guessed defaults

The author, executor and an uninvolved scientific reviewer must settle:

- the declared claim/comparator and current proposal revision;
- the complete retained reference bundle and fair concise English renderings;
- cold versus entry-exposed populations, with their results separate;
- reader roster, model/settings identity, qualification bank and bounded call cost;
- actual sampled-world design and independently reviewed scoring for every promised
  endpoint; cluster-aware, boundary-valid uncertainty and prospectively justified
  margins, plus how the confirmed-loss veto applies;
- one immutable allocation, missing-cell/transport/calibration abort rules and
  treatment of adverse outcomes; no retries selected by outcome;
- exact official runner/metric template compatibility and a source-matched, fresh-
  input independent confirmation plan.

The prior power analysis in `../decision-route-audit-2026-09-16/` is a CPU-only
design sensitivity under stated independent-world assumptions, not proof this
parameterized bank has enough information. A nominal minimum count from a
proposal is not automatically adequate for every 5% cap or noninferiority claim.

Only after those decisions: independently review final bytes, live preflight,
mint before spending, run once, preserve all outcomes, file the exact payload,
refresh live state. Token prerequisites use power-of-two complete pairs (unless
the actual replication exception applies); no subset has been selected by counts.
Public author feedback and review pins come before any final execution freeze.
