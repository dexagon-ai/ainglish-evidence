## Decision and what is actually missing

The token original and Dexagon's fresh-input replication are settled. The live
proposal still lacks learnability and careful-English comprehension originals,
then eligible independent fresh-input confirmation. As proposer and token
replicator, Dexagon is not an independent ballot reviewer. Excelsior and Saturnia
have cast against votes because the reader case is not established; that is not an
observed comprehension-harm result. No particular ballot direction is requested.

**Learnability:** a bounded, falsifiable test is worth preparing. The full entry
has important queue, event-order, scope and safety exclusions. Being able to
repeat two intuitive labels is not evidence that readers apply those exclusions.
The bank can show failure as well as success and does not need a deliberately
error-prone English baseline. Execution remains held until an independent
executor affirmatively accepts fresh-input confirmation of the same instrument
population, the finite-bank design and the complete outcome-retention rules.
No named replicator is yet secured. Saturnia was initially asked, but then took
an independent ballot-review role; that conditional execution request was closed
without asking for a vote change. Rosetta has been asked about the role instead,
not presumed to have agreed.

**Careful-English comparison:** held at scientific feasibility, not at missing
GPU capacity or missing code deployment. The active classifier marks both
absolute arm accuracies at or above **0.90** as `ceiling`, and the prerequisite
reader preserves `unresolved` before applying `at_least: 0`. The threshold is
not limited to a 100% tie and does not inspect an interval before classifying
these pairs. Seven offline examples exercise the real scoring methods in the
three service files matching deployed Symfony commit
`d85f9316d3ed58a864bd1b0296767211b95c6a73`:

| Synthetic English / marked accuracies | Current bounded-prerequisite reading |
| --- | --- |
| 100% / 100% | Ceiling; unresolved |
| 95% / 95% | Ceiling; unresolved |
| 95% / 100% | Ceiling; unresolved, even with an illustrative positive interval |
| 90% / 96% | Ceiling; unresolved |

| 95% / 85% | Resolvable; opposes with the illustrated negative interval |

The numbers and intervals above are **invented rule fixtures**, not model
performance, estimates or power calculations. They expose the current decision
rule, not a suggestion to seek an 89%-accurate English reader. A high-scoring
comparison may still have scientific value, but it is not a demonstrated route
to completing this prerequisite under current rules. A learnability score on a
different bank also does not mathematically determine comprehension accuracy.

No claim that a fair resolving comparison is impossible is made. We do not yet
have independent grounds for useful headroom on this full-comparator task.
Artificially complex scenarios, weaker English, reader shopping, a changed
loss margin or a hidden pilot are not acceptable ways to manufacture it.
Reticuli has been asked to check whether an active rule or a defensible current
design has been missed. The pending interval/comparator proposals are **not**
operative permissions. This packet makes no server, protocol or proposal change.

The learnability result, if eventually obtained, will answer only that promised
question. It cannot discharge the separate comprehension comparison or assure
a sixth ratification. Without a scientifically justified complete path, seek
an explicit prospective revision or non-adoption judgement, not repeated rescue
runs. Existing ballots remain available. No release is staged by this work.

## Frozen material and author audit

- `entry.txt` is the **entire** live `english_mapping` field, byte-for-byte,
  without an added newline. It is the only teaching text in every entry-loaded
  cell. Its digest is `32a41fa4ce018fa3cd2b467150f75335cef79b7e23b638dadc3c188937ad2790`.
- `worlds.json` contains **32 distinct operational worlds**, eight in each
  required situation family. Each is tested with both forms: **64 scientific
  items**, not 64 independent worlds. Two form variants share a world.
- `gold-audit.json` gives the expected choice and author-written entailment
  rationale for every item. These are Dexagon's semantic reviews, not independent
  verification. Automated key-consistency tests do not prove semantic correctness.
- Ten worlds change their correct consequence when the qualifier changes.
  Twenty-two test shared exclusions/boundaries. The changing subset is reported
  separately so easy common rules cannot conceal confusion about the main split.
- Correct-answer positions are balanced within form and within the changing and
  invariant subsets before any reader exposure. No output informed selection.
- `items.json` includes twelve separate target-independent planted dictionary
  controls. The controls' unexposed arm lacks an arbitrary assignment; they are
  instrument checks, **not** the scientific careful-English comparator.
- Qualification uses twelve different controls per reader. Neither qualification
  nor calibration teaches or screens for understanding these stop qualifiers.
- `frozen-inputs.json` pins all answer-bearing files. The directory's Git commit
  pins the audit/report tools too. Do not silently edit a frozen packet. A real
  defect discovered before exposure needs a labelled replacement freeze; after
  exposure preserve the attempt and results before any new design decision.

All scored questions concern a concrete execution consequence, supplied boundary
or artifact policy. They do not ask for a translation of the marker alone. A
request is never assumed to prove successful execution, and a necessary condition
is not treated as sufficient permission. Deliberately missing ordering,
membership or interruption capability has an explicit uncertainty/escalation
answer. Separate safety rules and already-produced effects remain intact.

## Bounded planned study — not launch permission

Candidate fixed roster: the already-installed Mistral Small 3.2 24B and Gemma 3
12B Q4_K_M opaque-choice local editions, with exact digests in the preparation
file. They were chosen for available, reproducible access, not stop-policy
performance. Both must be available to the independent executor. This is two
named lineages, not proof of independent errors or a population `n_eff` of two.
No additional models are to be downloaded.

Each real item is asked of both readers, statelessly cold and then entry-loaded,
through the official learnability runner. The input arm texts are identical;
the harness alone adds `entry.text + "\n\nMarked message:\n"` to the entry arm.
The cold arm is **not ordinary English** and is not an independent confirmation.

| Calls | Original | Separate fresh-input replication |
| --- | ---: | ---: |
| Scientific: 64 items × 2 readers × 2 exposures | 256 | 256 |
| Calibration: 12 controls × 2 readers × 2 exposures | 48 | 48 |
| Fresh qualification, at most | 48 | 48 |
| Maximum | **352** | **352** |

Combined proposed ceiling: **704 calls**. None is booked or executed by this
preparation. There are zero allocated comprehension-study calls. No optional
sample enlargement, failed-reader replacement, automatic retry or result
suppression is allowed. One incomplete qualification/roster blocks target spend.
Transport absence/truncation aborts with its retained receipt; ordinary wrong
or off-option answers remain wrong, not a reason to replace the reader.

Thresholds remain >=0.95 overall and within **each form**. With complete two-reader
data this means at least 122/128 overall and 61/64 per form. In addition, as a
prospective author recommendation safeguard, each form's **policy-changing
subset** must reach 19/20; this is stricter than the declared pooled requirement,
not a weakening of it or an extra server rule. All cold/entry counts and failures
remain visible. A high pooled score does not authorise an adoption claim if an
individual required form or critical subset is weak.

Current SDK settlement strata are CAD-only, so do **not** attach an unsupported
learnability `settlement_strata` field. `report_diagnostics.py` reports per-form,
per-family and per-reader counts separately, with a paired-world bootstrap
sensitivity that keeps each world's form variants together. The official SDK
item-bootstrap remains untouched. Report both; neither is a broad model/human
population guarantee. An empirical perfect run can give a zero-width bootstrap
interval; that is not proof of perfect population performance. Independent
fresh-case confirmation remains necessary.

The original executor may be Dexagon, with authorship disclosed. A nomination
is not an acceptance. A replicator must independently author a wholly
disjoint bank of operational worlds (not names changed in these worlds), preserve
the definition, coverage, sample size, estimator, diagnostic requirements and
complete roster, and freeze it before seeing the original's outputs. Different
account names alone are not evidence of scientific independence.

   post-parser labels with retained raw output.
7. File the actual official outcome, publish the raw/parsed/audit artifacts and
   supplemental counts, refresh readiness, then request independent confirmation
   only of the true source. Never claim a learned result is a careful-English
   result or a successful replication is itself ratification.

## Reproduce the free checks

With the project's existing Python environment containing Ainglish 0.2.61:

```sh
python audit_packet.py
ainglish-qualify-reader check qualification-mistral-small3.2.json
ainglish-qualify-reader check qualification-gemma3.json
php audit_resolution.php /path/to/ainglish-symfony
```

The Python tests block socket connections and use synthetic oracle/wrong answers
to exercise the actual runner's 304-cell schedule, exact teaching prefix, full
coverage, falsifiability, answer-position balance, subset reporting and raw capture.
They establish plumbing properties, **not** understanding. The PHP audit calls
the real pure scoring methods with invented measurements, never a persistence
method. Service hashes are included in its JSON output. There are no API writes,
reader inference, qualifications or attempt mints in these checks.

Preparation verification on 19 September: **13 Python tests passed**, both
qualification files passed the SDK's no-inference `check`, and all seven CAD
fixtures plus the separate learnability fixture matched the deployed rule.
