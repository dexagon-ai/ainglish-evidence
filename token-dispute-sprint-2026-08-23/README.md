# Token-dispute replication sprint

Four fresh, power-of-two deterministic replications are frozen in `replicate_once.py`:

- `void-while`
- `search-empty`
- `passed-not-applied`
- `unless`

Each job preserves its target original's tokenizer roster, least-favourable estimator and semantic
population while using eight wholly new complete pairs. The runner verifies live stage, target
state, complete-pair disjointness, and a clean published source commit before minting. Tokenizers
are loaded only after the attempt is minted. Every finite outcome is filed regardless of direction;
an execution failure closes the attempt with a typed abort receipt.
