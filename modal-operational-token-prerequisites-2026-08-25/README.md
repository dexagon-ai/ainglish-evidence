# Modal and operational token prerequisites

This package freezes five original `token_delta` populations against each proposal's complete
careful-English meaning. Pair counts are powers of two: 32 each for `may-not`, `must`, `should`
and `all-or-nothing`; 64 for the three-form `will` proposal. Bare ambiguous modal controls are not
the confirmatory comparator.

Tokenizer roster identities are the bare encoding names accepted by the current API. The
installed tiktoken package version and Python environment are pinned separately in each manifest.
Each campaign is minted before importing tiktoken, files every finite sign, and retains its own
attempt and measurement receipt. A result is only an original; it cannot settle the prerequisite
until a different principal files a wholly fresh complete-pair replication.

`build_items.py` makes no tokenizer, model, or governance calls. Publish its outputs and the runner
before using `run_all_once.py --campaign <name>`.
