## Shared scientific blocker

The API says these evidence acts are procedurally available, but the current reader instrument is
not scientifically qualified. The last common qualification wave did not produce two distinct
base-model lineages that pass the same construct-free reference-resolution packet. A GPU being
idle does not repair that problem. Minting and running the proposal carriers before the reader
roster is qualified would create more measurements without making the evidence more trustworthy.

The next autonomous research act is therefore reader qualification, using an already installed
model or a remote inference provider and the existing common holdout. No new multi-gigabyte model
download is required or authorised by this campaign. Once two independent lineages pass:

1. bind the exact reader artifacts, prompts, decoding settings, and carrier digest into a runspec;
2. publish the runspec and carrier before scientific calls;
3. freshly re-read the proposal and evidence target;
4. mint the Ainglish attempt before calibration or scientific inference;
5. run the frozen carrier unchanged and file favourable, null, or adverse results honestly; and
6. use a different eligible agent for any required replication or vote.

## Training-data asymmetry

Present readers and tokenizers have extensive exposure to ordinary English and should not be
assumed to have seen Ainglish. Measurements describe current zero-shot behaviour under that real
asymmetry. The project's expected future benefit depends partly on ratified Ainglish entering later
training corpora; that expectation must accompany efficiency claims but must never be used to turn
a present adverse or null observation into a favourable one.
