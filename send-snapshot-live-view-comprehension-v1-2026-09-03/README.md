# send-snapshot / grant-live-view comprehension carrier v1

This is the fresh 144-scenario claim carrier declared by proposal
`send-snapshot-version-ref-to-recipient-grant-live-view`. It compares each
compact form only with its full careful-English mapping; bare “share” is not an
accuracy arm because it does not reveal a hidden intended topology.

The scientific carrier is balanced across two forms, six human-readable
domains, four consequence events and three probe classes. Each row presents two
explicit questions. Its four answer options are the Cartesian product of the
two implementation poles and two consequence/boundary poles, so exact-pair,
implementation-only, and consequence-only accuracy can all be recovered from
the same answer. The boundary probes cover edit and
redistribution rights, separately authorised copies, delivery/opening proof,
and service reachability. Snapshot persistence is scored only when delivery and
retention are stated; live-view rows exclude an alternative grant or a copy
unless that separate copy is the explicit non-erasure boundary under test.

Twelve equal-weight form-by-domain settlement strata prevent either form or a
domain from hiding a loss. All forty-eight form-by-domain-by-consequence cells
required by the proposal remain separately reportable in the normalized-cell
sidecar, alongside the finer boundary-probe and independently scored question
breakdown. Those diagnostics must not be replaced by the pooled headline.

Eight construct-free controls execute first in both arms. `build.py` and
`audit.py` perform no model, network, or governance calls. After a run,
`score_components.py <cell-receipt.json>` recomputes implementation,
consequence/boundary, and exact-pair accuracy from every retained answer. The
carrier is frozen for Spark's already-qualified
`spark-zen-13-minimal@provider-served` reader against released SDK 0.2.52.
The provider is opaque and this is present zero-shot evidence from a model
trained primarily on ordinary English, not a claim about future Ainglish-aware
training. The panel entry sets `model_catalog` explicitly to `null`: omission
would inherit OpenCode Zen's mutable `/models` binding from the SDK preset.

`activate.py --sdk-commit 4f496865774c445b9cc9cdc3ce3beb5d9ecfd57a`
binds the public carrier, exact qualified-reader receipt, all 12 settlement
strata and 48 reported consequence cells, and a frozen seed whose one-reader
deal exposes both arms in every settlement stratum. The committed
`runspec.json` is that sub-20-KB output.

The measurement principal should install exactly `ainglish==0.2.52`, export an
Ainglish credential and `OPENCODE_API_KEY` only in their local shell, and run:

```bash
ainglish-panel run runspec.json --dry-run
python run_once.py
```

The first command makes no API or reader calls. `run_once.py` verifies the
frozen runspec digest, re-reads authenticated suggestions and the proposal, and
refuses unless this exact original comprehension carrier is still routed. It
then mints before the first real reader call and files or records a typed abort.
