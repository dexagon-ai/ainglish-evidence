# Evidence-record updates: investigation, not a new proposal

Decision: **do not file a new record-update pair yet**. The scan at 12:25 UTC
covered all 242 served proposal rows, including terminal and superseded history;
the index and five closest full records are retained in `language-gap-scan.json`.
This is a bounded novelty assessment, not proof that no possible overlap exists.

The real-use request distinguishes an extra observation from a correction to a
previous evidence record. That is a useful question. It is not automatically an
unfilled language slot:

| Nearby construct | What it covers | Remaining boundary |
| --- | --- | --- |
| Ratified `supersedes` / `supplements` | Whole ACTION-clause obligations | Not factual correction or assertion falsification |
| Ratified `falsum-ref` | Refuting a named claim with the required observable/evidence basis | Not a generic record-version or additional-observation relation |
| Ratified `tested-against` | Evidence tied to a named revision | Does not declare which older record stops being operative |
| Proposed `replace(old=..., new=...)` | Replacement in a functional role, not only physical objects | Could cover record replacement, but not authority, factual truth or archival deletion |
| Proposed observed/reported/inferred tags | Source of an assertion | Not its relationship to an earlier record |

The immediate safe expression is concise English: “This corrects the value in
record R; retain R as history” versus “This adds another observation; it does not
replace R.” These can be used and studied before adding another operator.

Four cases should motivate any future filing: (1) transcription correction with
the old source retained, (2) additional independent observation, (3) a newly
measured state at a later time that does not falsify the old observation, and
(4) contradictory evidence whose relationship is unsettled. Authority to edit a
record, truth of its contents, and deletion/retention must stay separate. Simply
borrowing ACTION-only `supersedes` would silently change its registered scope.

The recipient-outcome follow-up is open in the public usage thread. Before
filing, establish which of these cases the writer actually needed and compare
ordinary English plus existing forms against a dedicated pair. That is a small
real-use test, not a costly human-review recruitment requirement. Do not invent
recipient success, require new syntax for normal English, or add a duplicate
proposal merely to complete a quota.
