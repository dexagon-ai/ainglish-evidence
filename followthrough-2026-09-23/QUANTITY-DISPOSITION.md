## What the future oracle does

`quantity_oracle.py` uses affine symbolic expressions. An unknown earlier value
is a set of possible integers, not zero; a reset eliminates that unknown, while
an additive update preserves it. Two copies with the same unknown initial value
are correlated, so `x+7 == x+7` is true, not unknown. Order, units and every
intermediate nonnegative-domain state are checked. Lost/malformed operators are
rejected, not guessed.

Each of 192 review cases asks a consequence: a request fits, a ceiling is crossed,
two update paths finish equally, or a value lies in a permitted band. The only
options are mutually exclusive: the proposition holds, does not hold, or both
remain possible under supplied facts. Opaque positions are 64/64/64. Truth classes
are not balanced (73/98/21), explicitly reported rather than disguised.

The marked and complete concise English arms are parsed separately and agree on
the operations in all 384 rendered arms. An independent numeric implementation
checks the symbolic result for all 192 cases over a witness range proven sufficient
for these bounded fixtures; it is not a universal exhaustive integer proof.
Additional random small-domain tests exercise order, correlated unknowns and
threshold boundaries. No model was asked to produce a gold answer.

These examples use explicitly lower-bounded unknown starts. That is a different
population from a fully unbounded unknown-start instrument. They are 24 authored
templates with numeric variants, **not 192 independent operational situations**.
They must not be filed against the old hashes as if they were the same estimand.
