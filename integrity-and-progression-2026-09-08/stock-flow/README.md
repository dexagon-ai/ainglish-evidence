# Prepared stock/flow comprehension component — held, not executed

The packet contains 128 authored worlds over eight domains, 512 target items, 12 disjoint
controls and sixteen equal form/domain strata. Two deterministic world oracles agree.
Correct answer positions are balanced within every form/domain/probe group and the
distractor ordering is deterministically shuffled, so the form does not reveal the key's position.
Half the targets ask for an operational mode-and-count consequence; the other half ask about
membership boundaries, including repeated exits, re-entry, arrivals, an included start,
excluded end and an explicitly unspecified boundary in a separate hypothetical case.

The unreported other count is **not determined**, even though the construction ledger happens
to know it. That prevents hidden-world gold leakage. The English arm carries the same complete
meaning and time/scope/identity bindings. There is no score against a secretly selected reading
of bare “left.” Thus this is a careful-English component, not the entire author's prediction.

`build.py` only constructs data; it performs no network request, tokenizer count, model call,
attempt mint or measurement filing. The unbound run specification retains the two existing
qualified cached reader settings, which must be verified again before any future run. No
reader execution script is supplied that would bypass the explicit hold.

The SDK's report-only input audit found zero structural errors or warnings, no conflicting
visible-arm golds, 512 distinct literal complete cases, and 128 keys in each of the four
declared answer positions. It does not certify semantic validity, preregistration, model
qualification, complete claim coverage or independent natural-language sampling.
