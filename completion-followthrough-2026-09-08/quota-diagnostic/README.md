# Quota component diagnostic — prospective, separate study

This is not the held bare-English companion, not a replication of the earlier
inconclusive study, and not a full-claim or future-trained performance test.

The previously filed careful-English result remains +4.65 percentage points,
interval [-7.6181, +17.6391], with English 43.27% and Ainglish 47.92%. This new
study asks where those two specific cached readers struggle, using four separate
32-item strata: fixed/sliding **rule selection without arithmetic**, and
fixed/sliding **small-number counter evaluation with explicit enforcement rules**.
It does not isolate a single causal mechanism: questions and context differ
between components, which is why their scores must be reported separately.

The 128 target rows use eight authored domains, simple UTC clock times, and
independently checked finite counting rules. Ten unrelated sensitivity controls
precede all target calls. Qualification/control success does not certify quota
task competence. All outputs, failures, absolute accuracies and null/adverse
comparisons must be retained. Related templates are not independent natural-use
samples, and the pooled headline is not a four-condition adoption decision.

The authoritative mint-ready plan is under **registered-plan/**. The initial
unbound preparation failed the 20KB reader-manifest check before mint; the final
plan references the already published inputs by immutable commit and hash.
The statement-only token preparation also correctly refused duplicate statements
used with different questions. The final prospective cost bridge counts the
complete already-frozen statement, identical question and answer choices (not
the gold key), preserving all 128 unique complete inputs. No meaningless padding,
post-inference redesign or silent reduction in coverage was used.

Execution requires an unchanged active proposal, successful server preflight,
the current formal cost prerequisite, and a freshly minted matching-cell bridge
within +1 on every declared stratum/tokenizer. It uses only the already cached,
qualified Falcon3 and OLMo2 artifacts. No new models, unrelated workload eviction,
target retries, threshold relaxation or automatic reruns are authorised by this
plan. A failed gate is a retained hold/abort, not a reason to choose another model.

The earlier bare-English companion remains held under its own original gate;
this new diagnostic does not revise that decision.
