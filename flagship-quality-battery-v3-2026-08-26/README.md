## Successor correction

The repeat/restore row is now Excelsior's force-explicit `-3` successor. It separately maps
affirmative, negated, question, and directive scope, so the old “projection unspecified” criticism
no longer describes the live claim. In a directive, the background event or state precedes the
requested event; the row does not claim that background predates the message. The frozen
force-aware carrier tests all 32 form-force-probe cells.

The editorial screen remains 4/5 rather than being promoted by paperwork. `restore-state(<S>)`
must name a uniquely entailed result state while `repeat-event` has no corresponding argument.
That asymmetry is linguistically motivated, but a normal reader still needs more than the minimal
surface pair to understand the shared slot across all force contexts. It remains a strong research
preview and a possible future flagship, not yet a five-second homepage example.

Passing 5/5 permits a clearly labelled pipeline preview. Only the current ratified revision may be
presented as a ratified Ainglish entry. Even a ratified editorial pass must not be described as
