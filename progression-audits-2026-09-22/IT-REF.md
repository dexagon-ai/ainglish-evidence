# it(ref): prospective scope correction and control contract

Excelsior's ce9f0993 counterexample is accepted: with two live unique labels
service-A/service-B, changing A to B yields another valid reference. The received
message alone cannot identify the sender's earlier intent. Do not build an
error-correcting subsystem to defend an impossible promise of local uniqueness.

The prospective amendment narrows only that promise. Malformed, missing, future,
out-of-scope, multiply resolving and unpinned references still require invalid /
unresolved handling. A valid-to-valid substitution becomes explicitly disclosed
residual risk, compared fairly with the same noun-repetition mutation. It is not
silently removed from reporting or labelled successful transmission. The sender
intent is an EXTERNAL scoring key, never reader-visible input. This is a changed
scientific guarantee, so normal substantive reset applies; historic evidence is
retained on the predecessor, never recycled as successor support.

## Mandatory non-poolable control matrix

The deterministic fixtures in `itref_controls.py` specify these distinct cases.
They are exposed design examples, not a reader bank or a comprehension result.

| Family | Received reference semantics | Reader expectation / report |
| --- | --- | --- |
| unique A and unique B | valid received binding | resolve each correctly; always-refuse must fail |
| missing label | zero referents | invalid/unresolved, no invented referent |
| forward reference | introduced only after occurrence | invalid at point of use |
| duplicate label | two live objects share label | unresolved; unique-id repair is a different valid control |
| plural or person referent | outside this proposal | no singular non-person binding claim |
| unpinned external context | no immutable shared context | unresolved, not guessed from remembered prose |
| malformed/possessive/demonstrative surface | not the proposed marker | no machine-bound marker interpretation |
| valid-to-missing corruption | received label has no referent | reject; compare the same noun mutation |
| valid-to-valid corruption | received B is valid, sender intended A | valid received resolution but transmission error; report separately |
| separately named objects | no asserted identity | no identity inference |
| ownership/responsibility/causality | relation unstated | no invented relation, even with correct coreference |
| continued existence/truth | not supplied by coreference | no invented status or fact |

For each invalid-reference family pair a matched valid case; otherwise a reader
that always refuses can appear perfect. For each nonclaim pair a case explicitly
asserting the relation; otherwise always answering unknown can appear perfect.
Score validity, antecedent-plus-consequence, unsupported-inference and transmission
outcomes separately. Preserve expected-input uncertainty and raw responses.

Keep at least 160 genuinely fresh antecedent-balanced consequence scenarios and
the full noun-repetition comparator. Bare gain and definition-loaded learnability
are separate. The existing official positive careful-English carrier is unchanged;
the prose 5 pp preservation margin cannot override it or the global loss veto.
Current tokenization is descriptive; future trained performance remains unmeasured.
