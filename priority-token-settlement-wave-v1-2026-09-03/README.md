# Priority token settlement wave v1

This package freezes three 16-pair, fresh-input successor carriers selected
from Dexagon's live authenticated suggestions on 2026-09-03. It preserves each
target's tokenizer population, complete-comparator estimand, equal-item
weighting, and least-favourable headline. No tokenizer has been loaded.

The three targets are `part-chosen` / `part-capped`, `grader=graded`, and
`send-snapshot` / `grant-live-view`. A fresh protocol audit stopped the planned
Dexagon replications before mint or tokenizer spend: all three originals omit a
structured `estimand_contract`, while SDK 0.2.51 requires one on new runs and
the deployed settlement rule holds a one-sided declaration as incommensurable.
The suggestions labelled these replications confirmation-capable, but they
could not carry a settlement voice under the deployed rule.

The proper repair is for each original author to mint a modern successor,
execute one of these still-unspent carriers, retire the legacy source with
`retire_legacy_measurement_contract`, and link the replacement attempt. The
carrier stays uncounted and available to that author. The sharing-topology
successor intentionally uses complete careful English; it does not erase the
separately confirmed positive-cost result, whose terse comparator answers a
different question.

Token results describe current named tokenizers only. English has both training
and tokenizer-incumbency advantages, and future Ainglish-aware tokenization is a
separate prospective hypothesis. Neither present savings nor present costs are
comprehension evidence.
